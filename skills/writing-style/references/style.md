# 六个骨头的写作规范

本版以用户明确指定人工比例较高的《高考数学中可用的公式定理与使用建议》《利用 nftables 搭建 Linux 网关》为主要证据。Incus 与 `__eq__` 文章仅辅助对照，不推断其人工比例。原文观察及编辑建议见 [examples.md](examples.md)。

以下是本次任务采用的写作规则；“历史习惯”不等于每处都应模仿，修改示例也不等于作者已逐句认可。

## 从具体问题展开

- 开篇交代读者会遇到什么问题、本文准备解决哪一部分。原稿有真实个人动机时保留；没有时从问题本身写起，不补“我踩过坑”“研究了几天”等经历。
- 让章节回答问题的下一步。定义、机制、例子、边界按理解需要安排，不为了凑齐背景、优势、应用、总结而增加章节。
- 用途决定展开程度。高考笔记关注方法何时有用，网关文章关注需求与选型，Incus 笔记直接进入操作；这些是文体差异，不归纳成统一的短文偏好。

## 解释到读者能继续推下去

- 首次使用符号和术语时交代含义与作用；只展开读者缺少的前置知识，不加百科背景。数学方法说明适用条件，再给关键推导和能检验该条件的例子。
- 一句话变短后，主体、条件、因果、时序、例外和结论仍应完整。删除重复介绍和装饰，保留读者无法自行补出的中间步骤。
- 代码和公式之后解释它解决了什么、为何成立或如何判断成功，不逐行把符号读一遍。可以省略重复算术，不能跳过决定结论的步骤。
- 操作前说明必要环境、权限或依赖；把成功检查放到适当位置。历史配置与当前实测分开，不把旧文章重写成未经验证的最新版教程。

## 让判断有落点

- 保留作者能解释的偏好和取舍。例如，配置难备份可以支持个人迁移决定；不能由此推出另一个系统在性能上普遍更差。
- 分清“原文记录的体验”“个人选择”“有来源或验证的事实”“尚待验证的推断”。根据证据使用自然表述，不给每句机械贴标签。
- 比较方案时说明差异来自什么机制、约束或成本，优缺点标签只作为索引。表格后补必要解释，不再重复整张表；结尾只保留新增的判断、边界或未解决问题。
- 不把“高手／菜鸟”当能力论证，也不把“没用过”“不适合我”改为普遍否定。对缺少依据的绝对判断，补证据或收窄范围，不能暗中改成另一项断言。

## 保留自然表达

- 可以直接说“我选择”“对我来说”“这里用不到”，前提是材料支持。保留有信息的括注、犹豫和修正，不把所有第一人称删成中性说明书。
- 中文能清楚表达时少混用英文；保留精确术语、标识符、命令和必要英文名称。标点、标题和中英文空格遵循所在项目。
- 连贯的因果用段落表达；并列比较用表格，真实步骤用列表。加粗用于读者确实需要定位的内容，不给每句话加标签。
- 删除没有具体依据的“优雅”“显著提高”“首选方案”，以及只重复前文的收尾。不是禁词表：讨论这些词、引用原话或有充分依据时可以保留。
- 不强制句长、段落长度、第一人称比例、三段式结构或统一结尾。不靠加入口语、感叹和情绪制造“人工感”。

## 文体适配

| 文体 | 主要任务 | 编辑尺度 |
| --- | --- | --- |
| 数学与技术教程 | 帮读者理解并运用方法 | 保留定义、关键推导、例子和失败条件；精简反复计算与重复证明 |
| 操作笔记 | 让读者在指定环境完成操作 | 直接交代环境、步骤和验证；需要解释非显然机制时再展开 |
| 设计与方案讨论 | 让读者判断为什么这样选 | 写清需求、机制差异、代价与限制；不堆抽象评价 |
| 明确要求个人文风的 README、PR 等 | 完成该文体本来的任务 | 只应用准确、具体和有依据的判断，不自动扩成教程 |

## 完稿判断

读者能否回答本文的问题，理解公式与命令的前提，并区分作者选择与普遍结论？与原稿比较，是否丢掉了必要信息、添加了未经确认的经历、保留了可纠正的错误，或仅把重复内容换了说法？对照最相关的样例判断即可，不按字数下降或“像本人程度”评分。
