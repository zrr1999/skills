# 解释概念

帮助用户把一个陌生概念接到已有知识上，理解它为何有用、如何起作用，以及何时不能
这样理解。默认在对话中直接解释；深度由问题决定，不固定新手口吻、篇幅或章节。

## 找到需要解释的部分

从当前问题、前文和用户材料判断所指领域、已有知识与想解决的困惑。用户在一个领域
有经验，不代表已掌握另一个领域的前提。只补影响理解的前置知识，不例行询问学历、
水平或学习目标，也不从零复述用户已经展示的知识。

同名概念有多个含义，且上下文无法确定时，先简要列出相关含义并提出聚焦的问题。
能够合理判断时说明采用的含义并继续；不能把自己的假设说成用户的背景。
遵守明确的简答、深入推导或不用类比等要求。

## 建立可用的理解

先用准确、直接的话说明概念是什么，再围绕用户真正关心的问题展开。根据理解缺口
选择以下材料，不把它们变成每次必须填满的模板：

- 具体问题或限制：没有这个概念时，什么难以描述、解释或完成。
- 定义和机制：关键对象如何关联，哪些条件使结论成立；解释因果和中间步骤，
  不用另一组未解释的术语替换原术语。
- 一个足以说明机制的例子：追踪输入、变化与结果，或展示关系成立的理由。
  区分假设例子、引用的事实与实际运行结果。
- 容易混淆的相邻概念或反例：指出决定性的区别，以及解释的适用边界。

同一概念保持术语一致，首次出现的符号与必要缩写交代含义。简化时保留条件、否定、
量词、时序和例外，不把“通常”改成“必然”。专业术语可以保留，只解释当前所需部分。

类比只有在对应关系清楚时才使用。说明它映射了什么，并指出会影响理解的失效处；
不能从类比中推出目标概念没有的性质。没有合适类比时，直接用实际例子。

用户需要严谨定义或推导时，说明符号、假设和关键推理；不以“直观上显然”跳过决定
结论的步骤。用户只需要概览时，不为完整性强行展开证明、历史或分类。

## 选择证据与表达

遇到不熟悉、存在争议或版本敏感的事实，读取可靠的一手资料；用户指定材料时读到
相关原文。把引用放在支撑的论断附近，区分通行定义、某个作者的约定与自己的推断。
无法核实时说明具体缺口，继续能可靠解释的部分，不虚构来源或最新结论。

连贯推理用段落，真正并列的差异用表格，步骤用于顺序操作。结构、因果或动态变化
难以用短文说明时，可使用当前环境提供的图示或交互可视化；图中的标签与正文一致，
没有工具时用文字或简单图也能完成解释，不把制作视觉产物变成前置条件。

完整博客、教程或讲稿有各自的交付流程；需要组合时，本 skill 只负责概念解释，
不接管文章落盘、个人文风、仓库修改或发布。

## 回应理解反馈

发出前检查：定义是否准确，例子是否真的展示机制，结论是否保留必要条件，是否
引入了更多没有解释的概念。只输出理解所需的内容，不报告内部检查清单。

用户说仍不理解时，利用其反馈定位断点，改用更小的例子、另一种表示或补上缺失前提。
若无法判断困惑位置，问一个具体问题；不要只是同义改写整段答案。
只有用户要求互动练习或检验理解时才安排问题，不默认测验或要求复述。
解释已经回答当前问题时结束，不用固定的延伸问题或总结重复全文，也不宣称用户已经掌握。
