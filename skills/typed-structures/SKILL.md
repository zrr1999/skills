# Typed structures

这是一份**表达语言**的设计稿：用 `type` / `case` / `fn` / `law` / `def` / `proof` / `:>` 写结构、定律和子类型，而不是可运行实现。没有对应编译器；例子里的 `proof` 是显式写出的证明项，不是机器核验结果。

## 使用

1. 先读 [grammar.ohm](grammar.ohm)，再读 [examples.md](examples.md) 里对应主题。沿用同一份表面，不要翻译成别的语言。
2. 语义、填补规则和拒绝条件以本节为准。
3. **凡是新写或改写的程序，交给用户之前必须通过下面的 Ohm 检查。** 未通过就不要当作交付。

产出必须是该语言的文本。需要说明时，分开写：观察到的句法、拟议的含义、以及尚未决定的部分。不要把提案中的写法写成已经可用的产品命令。

## 句法检查（必须执行）

Ohm 只做识别：文本是否符合 [grammar.ohm](grammar.ohm) 的形状。它**不判定**种类默认、成员能否填写、证明是否成立、子类型路径是否唯一、索引是否匹配。检查通过不等于程序可接受。

使用官方 CLI `@ohm-js/cli` 的 `ohm match`。精确 flags 以本机 `ohm --help` 和 `ohm match --help` 为准。本机没有 `ohm` 时先全局安装，优先 pnpm：

```
pnpm add -g @ohm-js/cli
```

没有 pnpm 时：

```
npm install -g @ohm-js/cli
```

不要用 npx、不要在项目或 skill 目录里再装一份。若 `ohm match` 报找不到 `ohm-js`，再全局补上 `ohm-js`（同一包管理器的 `-g`）。

`<skill-base-dir>` 是本 `SKILL.md` 所在目录。把程序写入文件后执行：

```
ohm match FILE -f <skill-base-dir>/grammar.ohm -g TypedStructures
```

成功时静默、退出码 0。失败时 Node 会连带打出 stack；只看 `Error: Line …` 到 `Expected …`，按行号修改再跑，直到退出码 0。

- 检查单位是 `Module`（文法第一条规则：一串顶层声明）。单独表达式先包进声明再查。
- 新写、拼接或改过的 `type` / `let` / `def` / `proof` / `forall` / `:>` 都必须先写入文件再检查；不要只放在回复里。
- 原样引用 [examples.md](examples.md) 且未改动的片段可以不重复检查。行文中的短名字（如 `Option.Some`）不必检查。
- 反例不要放进围栏代码块；用缩进或行内代码。
- 改 [grammar.ohm](grammar.ohm) 或 [examples.md](examples.md) 之后，把例子代码块抽到临时文件再 `ohm match`。

向用户交付时说明检查已通过。失败未修好就把程序当作最终结果，算没有遵守本 skill。

## 语义规则

1. **记录与选择**：`type` 里没有 `case` 时是记录；有 `case` 时选择其中一个构造分支。`case` 外的数据 / `fn` / `law` / `def` / `proof` 属于所有分支；`case` 内的字段只属于该分支。构造值时必须提供公共字段和所选分支的字段，不复制其他分支。
2. **构造**：构造器统一为 `Type.Case`。位置参数写成 `Type.Case(...)`；具名字段写成 `Type.Case { ... }`。记录值写成 `{ field: value, ... }` 或 `Type { ... }`。`match` 里 `{ field, ... }` 只选择具名字段；`...` 忽略其余字段，不做复制。
3. **成员角色**：
   - `name: T;` 待提供的数据字段
   - `fn` 待提供的函数字段，只有签名
   - `law` 待提供的证明字段，返回类型是要证明的命题
   - `def` 已有固定定义，构造者不能覆盖
   - `proof` 已给出的证明；记录构造里的 `proof` 可以填补对应 `law`
   - 用 `def` 填补 `fn` 是定义抽象成员，不是覆盖已有 `def`
4. **不可填的固有成员**：`type` 里的 `def` / `proof` 不属于构造器可填写字段。它们依赖同一结构的字段，可以被调用，不能被重新提供。不存在可覆盖的“默认方法”。
5. **参数默认**：`[A, B]` 省略种类时按 `[A: Type, B: Type]` 理解。值索引必须标注，例如 `n: Nat`。高阶类型必须标注，例如 `F: Type -> Type`。`fn pure[A](value: A) -> F[A];` 与 `pure[A]: A -> F[A];` 表示同一个多态函数字段；主例保留前者，不要并列重复声明。
6. **计算模型**：纯、全函数；数据是不可变值。`Int`、`Bool`、`Str` 是已知基础类型；`Nat` 由例子给出归纳构造。`Type` 在表面中出现，不表示采用 `Type : Type`。函数箭头右结合。`(A, B)` 是二元组；`(A, B) -> C` 是两个参数的调用签名。`~=` 是相等命题，不是布尔计算；`==` 用于已有判定算法的布尔比较。本模型没有日志、资源或外部副作用。
7. **证明背景**（写证明体时只用这些，不要让读者猜）：
   - `refl`：两侧经定义展开和计算后相同
   - `symm(p)`：由 `x ~= y` 得到 `y ~= x`
   - `trans(p, q)`：由 `x ~= y` 和 `y ~= z` 得到 `x ~= z`
   - `congr_arg(f, p)`：由 `x ~= y` 得到 `f(x) ~= f(y)`
   - `funext(x => p(x))`：由逐点相等得到函数相等；本模型采用函数外延性
   - `match`：按构造器分支，并据此细化目标
   - `proof name(args) { ... }`：填补 `law` 时可继承完整签名与类型参数
   这些是例子列明的逻辑背景，不是在确定未来全部逻辑基础。
8. **子类型**：`S :> T` 表示 `S` 的值可用于需要 `T` 的位置。块给出目标缺失成员及证明；`self` 始终指源结构。目标已有的 `def` / `proof` 直接复用，不重新填写。空声明 `S :> T;` 仅在目标要求都能由源结构已有成员直接满足时使用。不根据名字偷偷选择全局实例，不把 `Type` 的参数自动填到其他位置。
9. **泛型关系**：用 `forall[...] { ... }` 显式绑定参数；这不是运行时循环。关系本身仍写成 `S :> T`，不写成转换函数签名。只登记单一路径；多路径须另行确认一致性，不能静默择一。
10. **注释与引用**：`///` 附着于声明；`//` 是局部说明。注释不增加定律。调用例子的结果必须来自定义或显式证明。顶层声明按完整文件解析，允许引用后文的辅助定义与证明。

## 应当拒绝

即使文法能识别，下列情况仍应拒绝（完整对照见 [examples.md](examples.md) 末节）：

- `fn` 带函数体；已有定义必须用 `def`
- 构造时覆盖类型里已有的 `def`
- `proof` 体只写出命题，没有证明项
- 未匹配就读取分支专有字段
- 给某分支提供其他分支的字段
- `case` 内重声明公共字段
- `refl` 用在定义展开后仍不相同的两项上
- GADT 构造器返回类型与标注不符
- 值索引不匹配，例如对 `Nil` 取非空 `head`
- 把子类型目标参数改到定义不支持的位置
- 把数据 ADT 本身当成操作结构（例如 `Option :> Monad[Option]`）
- 同一源到同一目标存在两条含义不同的隐式补全
- 换掉函数字段后直接复制旧 `law` 的证明

## 尚未决定

## 背景

定律与归纳类型的外部对照（不属于本语言）：GHC `Functor` / `Applicative` / `Monad`、Haskell 2010 `Control.Monad`、Agda record、Lean inductive 与 propositional equality。本语言的 `type` / `case` / `law` / `def` / `:>` 是独立草案。
